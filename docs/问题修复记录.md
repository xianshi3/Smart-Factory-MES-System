## 修复的问题

### 1. 数据库表缺少字段

**问题描述**: 多个业务表缺少 `deleted_time` 和 `deleted_by` 字段，导致逻辑删除时出错。

**受影响表**:
- `wo_work_order` (工单表)
- `pt_process_template` (工艺模板表)
- `pt_process_parameter` (工艺参数表)
- `qms_quality_record` (质检记录表)

**解决方案**: 执行 ALTER TABLE 语句添加缺失字段：

```sql
ALTER TABLE wo_work_order ADD COLUMN deleted_time DATETIME DEFAULT NULL;
ALTER TABLE wo_work_order ADD COLUMN deleted_by BIGINT DEFAULT NULL;
-- 其他表类似
```

### 2. 前端表单字段名与后端 DTO 不匹配

**问题描述**: 前端表单的字段名与后端 CreateDTO 的字段名不一致，导致创建失败。

**受影响字段 (工单)**:
| 前端字段 | 后端字段 |
|---------|---------|
| code | orderNo |
| name | productName |
| quantity | planQuantity |

**受影响字段 (工艺模板)**:
| 前端字段 | 后端字段 |
|---------|---------|
| code | templateNo |
| name | templateName |

**解决方案**: 修改前端 `WorkOrderView.vue` 和 `ProcessView.vue` 中的表单字段名。

---

### 3. 日期格式无法解析

**问题描述**: 前端发送的日期字符串格式 "2026-03-30:00" 无法被后端 LocalDateTime 解析。

**错误信息**: `Invalid format: "2026-03-30:00"`

**解决方案**: 
- 移除创建请求中的日期字段，让后端自动填充
- 或使用 ISO 格式 "2026-03-30T00:00:00"

---

### 4. 后端 DTO 验证注解导致 400 错误

**问题描述**: CreateWorkOrderDTO 使用了 `@NotBlank` 等验证注解，在字段名不匹配时直接返回 400 错误，无法看到真实错误原因。

**解决方案**: 临时移除 DTO 的 `@Valid` 注解。

---

### 5. JavaScript Long ID 精度丢失导致删除失败 (核心问题)

**问题描述**: MyBatis-Plus 使用 Snowflake 算法生成的 ID 超过 JavaScript Number 的安全整数范围 (2^53-1)，导致 ID 在前后端传递时精度丢失。

**示例**:
- 数据库 ID: `2042490503953403905`
- JavaScript 接收: `2042490503953404000` (精度丢失)

**错误现象**: 删除时查询不到记录 ("工单不存在")

**解决方案**:

#### 5.1 后端序列化时将 Long 转 String

在 `BaseEntity.java` 中添加 `@JsonSerialize` 注解：

```java
import com.fasterxml.jackson.databind.annotation.JsonSerialize;
import com.fasterxml.jackson.databind.ser.std.ToStringSerializer;

@TableId(type = IdType.ASSIGN_ID)
@JsonSerialize(using = ToStringSerializer.class)
private Long id;
```

#### 5.2 前端类型修改

修改 API 函数接受 string 或 number：

```typescript
// services.ts
export function deleteWorkOrder(id: string | number) {
  return request({ url: `/workorder/${id}`, method: 'delete' })
}
```

### 6. 乐观锁 @Version 导致更新失败

**问题描述**: 手动调用 `updateById()` 时，如果实体类使用了 `@Version` 注解，MyBatis-Plus 会自动注入乐观锁条件，但参数映射缺失导致 500 错误。

**错误信息**: `Parameter 'MP_OPTLOCK_VERSION_ORIGINAL' not found`

**解决方案**: 使用 `UpdateWrapper` 代替 `updateById()`：

```java
// 错误的写法
order.setDeleted(1);
updateById(order);  // 会触发 @Version 检查

// 正确的写法
var updateWrapper = new UpdateWrapper<WorkOrder>()
        .set("deleted", 1)
        .set("deleted_time", LocalDateTime.now())
        .set("deleted_by", userId)
        .eq("id", id);
mapper.update(null, updateWrapper);
```

### 7. 质量管理模块 - 创建和删除功能

**问题描述**: 质量管理模块缺少完整的创建表单和删除功能。

**受影响文件**:
- `mes-quality/.../QualityService.java` - 添加 deleteRecord 方法
- `mes-quality/.../QualityServiceImpl.java` - 实现删除逻辑
- `mes-quality/.../QualityController.java` - 添加 DELETE 接口
- `mes-quality/.../QualityRecord.java` - 添加 ToStringSerializer
- `mes-frontend/.../services.ts` - 添加 createQualityRecord/deleteQualityRecord
- `mes-frontend/.../quality.ts` - 添加 API 函数
- `mes-frontend/.../QualityView.vue` - 添加创建表单和删除按钮

**解决方案**:
1. 后端添加删除接口，使用 UpdateWrapper 避免乐观锁问题
2. 前端添加完整的创建对话框表单
3. 修复前后端字段名匹配 (result → checkResult, workOrderCode → workOrderNo)
