## 2. 总体设计

### 2.1 设计原则
- **高内聚低耦合**：最小化模块依赖
- **可扩展性优先**：为未来扩展设计
- **高可用与容错**：确保系统可靠性
- **数据驱动架构**：基于数据做决策
- **实时性与一致性平衡**：优化速度和准确性

### 2.2 总体架构
系统采用分层微服务架构：

│                      API网关                                 │
│               (Spring Cloud Gateway :8080)                  │
└─────────────────────────────────────────────────────────────┘
                               │
               ┌───────────────┼───────────────┐
               ▼               ▼               ▼
      ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
      │ 认证服务     │ │ 工单服务     │ │ 工艺服务     │
      │   (:8081)    │ │   (:8082)    │ │   (:8083)    │

### 2.3 架构特点
- **多语言协同**：.NET + Java + Python
- **流批一体数据处理**：实时处理与批量分析
- **事件驱动架构（EDA）**：通过Kafka异步通信
- **分布式系统设计**：微服务与服务发现

## 4. 核心模块设计

### 4.1 设备接入模块

#### 功能
- MQTT数据接收（EMQX broker）
- 数据清洗（去重、校验、异常过滤）
- 边缘计算（滑动窗口聚合）

#### 设计要点
- 异步处理（避免阻塞）
- 批量发送到Kafka
- 滑动窗口计算（10秒间隔）

#### 数据流
```
设备 → MQTT (mes/device/+/data) → .NET网关 → Kafka (mes-device-data) → Java服务
```

### 4.2 工单模块

#### 功能
- 工单全生命周期管理
- 报工处理

#### 状态机
```
CREATED → ISSUED → IN_PRODUCTION → PENDING_QC → COMPLETED → CLOSED
  ↓          ↓            ↓              ↓            ↓          ↓
创建     下发      生产中        待质检        完成       关闭
```

#### 关键设计
- 分布式事务（Seata AT模式）
- 幂等性控制

### 4.3 工艺模块

#### 功能
- 参数模板管理
- 实时参数校验

#### 设计要点
- Redis缓存已发布模板
- 参数版本控制
- 校验：值必须在min/max范围内

### 4.4 质量模块

#### 功能
- 质检记录
- 正反向追溯

#### 设计要点
- Elasticsearch索引搜索
- Kafka异步事件同步
- 追溯：SN → 工单 → 工艺 → 物料

### 4.5 看板模块

#### 功能
- 实时监控
- OEE计算

#### 技术
- WebSocket推送（5秒间隔）
- InfluxDB聚合查询
- Redis实时缓存

#### OEE公式
```
OEE = 可用率 × 性能率 × 质量率
可用率 = 运行时间 / (运行时间 + 停机时间)
性能率 = (理想周期时间 × 总产量) / 运行时间
质量率 = 良品数 / 总产量
```

## 5. 数据架构设计

### 5.1 数据分类

| 类型 | 存储 | 说明 |
|------|------|------|
| 业务数据 | MySQL | 关系型数据（工单、工艺、质量） |
| 时序数据 | InfluxDB | 设备指标、OEE数据 |

### 5.2 数据流

```
设备数据 → MQTT → Kafka → 服务 → MySQL/InfluxDB/ES
                     ↓
              AI服务（消费用于预测）
```

### 5.3 数据一致性

| 策略 | 使用场景 |
|------|----------|
| 强一致性 | Seata AT模式（工单事务） |
| 最终一致性 | Kafka + ES（质量事件） |

## 7. 非功能设计

### 7.1 性能设计
- **Kafka削峰**：缓冲高并发设备数据
- **批量写入**：MySQL批量插入、InfluxDB行协议
- **缓存优化**：Redis热点数据缓存，实时数据5秒TTL

### 7.2 可用性设计
- **服务冗余**：负载均衡后的多实例
- **熔断降级**：Sentinel熔断
- **健康检查**：Nacos实例健康监控

### 7.3 扩展性设计
- **微服务拆分**：按领域独立部署
- **无状态服务**：易于水平扩展
- **动态扩展**：K8s HPA（未来）

### 7.4 安全设计
- **JWT认证**：基于令牌认证，24小时过期
- **接口限流**：Sentinel流控
- **密码加密**：BCrypt哈希

## 8. 分布式事务设计

### 8.1 方案
Seata AT（自动事务）模式

### 8.2 事务流程

```
用户提交报工
       │
       ▼
┌──────────────────┐
│  开启全局事务    │
└────────┬─────────┘
         │
    ┌────┴────┐
    │         │
    ▼         ▼
更新      插入
工单      报工记录
    │         │
    ▼         ▼
更新      插入
设备状态  质检记录
    │         │
    └────┬────┘
         │
         ▼
┌──────────────────┐
│  提交全局事务    │
└──────────────────┘
```

### 8.3 风险控制
- **超时控制**：30秒事务超时
- **回滚机制**：失败自动回滚
- **重试策略**：3次重试，指数退避

## 9. AI系统设计

### 9.1 模型架构

| 模型 | 类型 | 用途 | 算法 |
|------|------|------|------|
| 质量预测模型 | 二分类 | 合格/不合格预测 | LightGBM |
| 产量预测模型 | 回归 | 产量预测 | XGBoost |

### 9.2 推理
- **运行时**：ONNX Runtime
- **特征**：温度、压力、速度、振动、运行时长
- **批量推理**：支持批量预测

### 9.3 特征工程
- 滑动窗口统计（60秒窗口）
- 聚合：均值、标准差、最小值、最大值
- 数据标准化

### 9.4 反馈闭环
```
设备数据 → Kafka → AI服务 → 预测结果 → 存入Redis
                    ↑
                    │
            检测到漂移时重新训练
```

## 12. 风险与挑战

| 风险 | 解决方案 |
|------|----------|
| 高并发写入 | Kafka缓冲+批量处理 |

| AI服务不可用 | 降级到规则预测 |
