## 1. 作品概述

### 一句话说明

> 在真实运行的 MES（制造执行系统）基础上，增加 AI Agent 生产助理层，让工厂管理人员通过**自然语言**即可完成设备监控、工单管理、库存查询、知识检索等生产任务，实现从指令下发到结果反馈的**完整任务闭环**。

### 核心能力矩阵

| 能力 | 实现方式 | 状态 |
|------|----------|------|
| ✅ 任务理解 | GLM-4 自然语言 → 意图识别 + 参数提取 | 完成 |
| ✅ 流程编排 | 多轮 function calling 自动拆解任务步骤 | 完成 |
| ✅ 工具调用 | 10 个 MES REST API 封装为 Tool | 完成 |
| ✅ 知识增强 | RAG 检索设备手册 / 质检标准文档 | 完成 |
| ✅ 多轮交互 | 前端对话历史 + 上下文保持 | 完成 |
| ✅ 结果交付 | 结构化回复 + 步骤可视化面板 | 完成 |
| ✅ 多模态 | MES 系统已有 3D 数字孪生场景（Three.js） | 完成 |

### 与赛道要求的对应关系

| 赛道要求 | 作品实现 |
|----------|----------|
| 面向真实行业场景 | 离散制造业 MES，已在设备运维、工单管理、供应链协同等场景运行 |
| 具备任务理解能力 | 自然语言输入 → GLM-4 解析意图和参数 |

## 2. 目标用户与场景痛点

### 目标用户

| 角色 | 痛点 | 使用场景 |
|------|------|----------|
| **生产班长** | 需要在多个系统间切换查询设备状态、工单进度 | "查一下 A 线所有设备状态" → 自动汇总 |
| **设备维护工程师** | 设备报警后需要查阅手册、创建维修工单、通知相关人员 | "DEV-003 温度 72°C，查一下手册怎么处理，创建维修工单" |
| **物料管理员** | 库存不足时需要快速了解库存并通知补货 | "查一下原材料 RAW-001 的库存" |
| **车间主任** | 需要综合了解产线运行情况 | "看看今天有哪些工单在执行，优先级 HIGH 的有哪些" |

### 典型场景：设备高温预警 + 自动处置

```
场景：设备温度异常

传统流程（5 步，约 15 分钟）:
  1. 打开设备监控页面 → 找到报警设备
  2. 记录温度数据
  3. 查询设备手册判断严重程度
  4. 打开工单系统创建维修工单
  5. 手动通知维修工程师

Agent 流程（1 句指令，约 30 秒）:
  用户: "查 DEV-001 温度，超过 55°C 就创建维修工单"
  系统: 自动完成设备查询 → 阈值判断 → 工单创建 → 结果汇总
```

### Agent 编排引擎（agent_service.py）核心流程

```
用户输入: "查 DEV-001 状态，温度高就创建工单"
        │
        ▼
┌─────────────────────────────┐
│  Step 1: 意图理解           │
│  GLM-4 分析需要获取设备信息  │
│  → 调用 get_device_detail    │
└─────────────┬───────────────┘
              ▼
┌─────────────────────────────┐
│  Step 2: 工具调用           │
│  get_device_detail(DEV-001) │
│  → 温度 68°C                │
└─────────────┬───────────────┘
              ▼
┌─────────────────────────────┐
│  Step 3: 条件判断 (LLM)     │
│  68°C > 55°C → 需要创建工单 │
│  → 调用 create_work_order    │
└─────────────┬───────────────┘
              ▼
┌─────────────────────────────┐
│  Step 4: 工具调用           │
│  create_work_order(描述,1,H)│
│  → 工单创建成功 #WO2401     │
└─────────────┬───────────────┘
              ▼
┌─────────────────────────────┐
│  Step 5: 结果聚合 (LLM)     │
│  汇总设备状态 + 工单信息    │
│  → 自然语言回复给用户       │
└─────────────────────────────┘
```

### 工具接口定义（tools.py）

| 工具名称 | 对应 MES API | 说明 |
|----------|-------------|------|
| `list_devices` | `GET /dashboard/device/list` | 查询所有设备状态 |
| `get_device_detail` | `GET /dashboard/device/{code}` | 查询单个设备详情 |
| `list_work_orders` | `GET /workorder/page` | 查询工单列表 |
| `create_work_order` | `POST /workorder` | 创建工单 |
| `list_production_lines` | `GET /dashboard/production-line/list` | 查询生产线 |
| `list_workstations` | `GET /dashboard/workstation/list` | 查询工位 |
| `list_boms` | `GET /dashboard/bom/list` | 查询 BOM 清单 |
| `list_materials` | `GET /dashboard/material/list` | 查询物料 |
| `get_inventory` | `GET /dashboard/inventory/list` | 查询库存 |
| `query_device_docs` | RAG 知识库 | 检索设备手册/质检标准 |

### 知识库设计（knowledge_base.py）

| 文档 | 分类 | 用途 |
|------|------|------|
| CNC 加工中心操作手册 | 设备手册 | 设备操作规范、日常保养 |
| 设备温度异常处理指南 | 设备手册 | 温度分级处理流程 |
| 产品质量检验标准 | 质检标准 | 外观/尺寸/性能检验规范 |
| SPC 统计分析标准 | 质检标准 | 控制图判异准则、过程能力 |
| 工单管理规范 | 业务流程 | 工单类型、状态流转、优先级 |
| 年度设备维护保养计划 | 设备手册 | 日/周/月/年维护计划 |

### 模型信息

| 模型 | 用途 | 来源 |
|------|------|------|
| **GLM-4-Flash** | Agent 推理、意图理解、工具选择、结果生成 | 智谱AI (免费模型) |
| **LightGBM** | 质量预测（产品合格率预测） | 自训练 ONNX 部署 |
| **XGBoost** | 产量预测（产能预测） | 自训练 ONNX 部署 |
| **BERT (sentence-transformers)** | 知识库向量检索（可选升级） | HuggingFace |

## 4. 技术路线

### 技术栈

| 层级 | 技术 | 用途 |
|------|------|------|
| 前端框架 | Vue 3 + TypeScript + Vite | 对话面板、3D 可视化 |
| UI 组件 | Element Plus | AI 助手 UI |
| Agent 框架 | 自研（基于 GLM-4 function calling） | 任务编排 |
| 大语言模型 | GLM-4-Flash（智谱AI） | 意图理解、工具选择 |
| 知识检索 | 关键词检索（Jaccard 相似度） | 离线知识库 |
| 后端 API | Java Spring Boot / Python FastAPI | MES 业务 + Agent 服务 |
| 数据库 | MySQL / Redis / InfluxDB | 业务数据 / 缓存 / 时序 |
| 消息队列 | Kafka | 设备数据采集 10000+ 条/秒 |
| 3D 可视化 | Three.js | 数字孪生场景 |

### 数据处理

```
设备数据流: 物理设备 → MQTT → .NET 网关 → Kafka → Java 后端 → MySQL/InfluxDB
                                                           ↓
                                                    Agent 工具调用查询
                                                           ↓
                                                    用户获得实时数据
```

## 6. 数据来源与合规边界

### 数据来源

| 数据类型 | 来源 | 说明 |
|----------|------|------|
| 设备状态数据 | 模拟设备（WPF 模拟器）通过 MQTT → Kafka 实时生成 | 非真实生产数据 |
| 业务数据（工单/物料/BOM） | MySQL 数据库，初始化脚本插入示例数据 | 脱敏测试数据 |
| 知识库文档 | 手动编写的设备手册和质检标准 | 模拟工业文档内容 |

### 数据授权与隐私保护

- **无真实用户数据**：所有数据均为测试环境模拟生成，不涉及真实人员信息
- **无商业机密**：设备参数和工艺数据为公开参考值，无企业特定数据
- **本地部署**：系统完全运行在本地环境，无外部数据传输
- **JWT 认证**：API 接口通过 JWT Token 鉴权，防止未授权访问

### 风险提示

- 本系统为**技术验证原型**，不直接用于真实生产环境
- AI Agent 的决策建议需由人工确认后再执行
- 大模型可能产生幻觉，关键操作（如创建工单）需人工复核
- 生产环境部署前需进行安全审计和压力测试

### 行业边界说明

- 适用范围：**离散制造业**（电子、机械、汽车零部件等）
- 不适用于：流程制造业（化工、制药等需特殊行业认证）
- AI Agent 当前聚焦：**设备运维** 和 **供应链协同** 两个子场景
- 知识库文档需根据实际工厂设备替换为真实手册

## 7. 部署方式

### 环境要求

| 依赖 | 最低版本 |
|------|----------|
| JDK | 17+ |
| Python | 3.11+ |
| Node.js | 18+ |
| Docker | 24+ |
| MySQL | 8.0 |

### 启动步骤

```bash
# 1. 启动基础设施（MySQL/Redis/Kafka/Nacos）
docker compose up -d

# 2. 编译并启动 Java 后端（6 个微服务）
mvn clean package -DskipTests -T 4
java -jar mes-dashboard/target/mes-dashboard-1.0.0-SNAPSHOT.jar &
# ... 启动其他服务

# 3. 启动 AI Agent 服务
cd mes-ai-service
pip install -r requirements.txt
# 配置智谱AI API Key
echo "ZHIPU_API_KEY=your_api_key" > .env.local
python -m uvicorn src.app:create_app --factory --host 0.0.0.0 --port 8087 --reload

# 4. 启动前端
cd mes-frontend
npm install && npm run dev

# 5. 运行前置检查
cd mes-ai-service && python check_agent.py
```

## 附录 B：与赛道评分标准对应

> Boundless Agents 赛道评分维度（参考）

| 评分维度 | 作品对应内容 |
|----------|-------------|
| **场景真实度** | 离散制造业 MES，覆盖设备运维和供应链协同真实痛点 |
| **任务闭环完整性** | 从自然语言指令 → 工具调用 → 业务执行 → 结果反馈的完整闭环 |
| **技术复杂度** | Agent 编排 + 多步推理 + RAG 知识增强 + 多工具协同 |
| **可演示性** | 本地可运行 Demo，前端可视化展示每步执行过程 |
| **创新性** | 在已有 MES 上增加 Agent 层，复用真实业务数据和 API |
| **可复用性** | Agent 框架可独立部署，Tool 定义可扩展，可作为工业 Agent 模板 |
| **文档完整性** | 架构设计、技术路线、部署方式、迭代计划完整说明 |
