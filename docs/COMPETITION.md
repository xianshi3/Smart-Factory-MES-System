## 一、作品简介（500 字以内）

项目名称：智能工厂制造执行系统 Smart Factory MES System
赛道：AI+工业制造——设备故障诊断 Agent
目标用户：生产班长、设备维护工程师、车间主任

核心问题：离散制造车间设备多、数据分散，传感器、告警、工单、维修手册各自为政，一线人员排障需跨系统手工翻查、依赖个人经验，异常响应慢、停机损失大。

解决方案：在开源 MES 上构建「AI 生产助理」设备故障诊断 Agent。基于智谱 GLM-4-Flash 的 Function Calling 多步推理，将自然语言指令编排为「查设备→看告警→析趋势→查手册→建维修工单」的完整闭环。Agent 通过 19 个 MES 工具实时调用数字孪生、告警、趋势、工单、质检、库存等后端接口，内置 6 篇设备/质检知识库（TF-IDF 检索）做知识增强，输出含数据表格与处置建议的结构化诊断报告。

创新点：①规则意图识别 + LLM 编排 + 工具调用 + 知识增强的四阶段工业 Agent，非泛聊天机器人；②数字孪生健康评分驱动「异常→根因→工单」主动闭环；③会话焦点记忆支持"那台设备"多轮指代。

开放/复用价值：全栈开源（MIT），微服务架构，模拟数据 + 设备模拟器零成本复现，工具层与知识库可插拔扩展。

当前进展：完整前后端可运行 Demo（3D 数字孪生看板 + AI 助理界面），正打磨诊断闭环与演示材料。

## 二、方案详细说明

### 2.1 场景来源与用户痛点

| 目标用户 | 关键任务 | 当前痛点 |
|---|---|---|
| 生产班长 | 盯线、快速响应设备异常 | 异常靠现场巡查发现，响应滞后 |
| 设备维护工程师 | 排障、维修、保养 | 传感器/告警/手册/工单分散在多个系统，人工翻查耗时 |
| 车间主任 | 掌握全局健康状态、安排抢修 | 缺少全局健康视图与处置闭环 |

**场景来源**：离散制造车间（CNC/PLC/机器人）设备状态实时采集但"数据孤岛"严重——故障原因需结合历史告警、运行趋势、维修手册和工单记录综合判断，依赖资深工程师经验，新人上手慢、停机损失大。

### 2.2 核心流程（任务闭环）

```
任务输入（自然语言）
   ↓
意图理解：规则+实体抽取（设备监控/健康总览/告警诊断/工单/知识/库存），自动提取设备编码
   ↓
任务规划：意图→工具链，注入执行计划提示（可灵活调整）
   ↓
能力调用：ReAct 循环调用 19 个 MES 工具 + TF-IDF 知识库（超时保护/去重/失败知识库兜底）
   ↓
结果交付：结构化报告（关键结论/数据表格/处置建议/后续追问），LLM 失败自动规则兜底
```

**演示闭环示例**："检查 DEV-003 温度高不高"
`get_device_digital_twin` → 健康评分 critical（78°C）→ `get_device_alarms` 查历史 → `get_device_trend` 看趋势 → `query_device_docs("主轴温度过高处理")` 取手册 → 建议创建维修工单。

### 2.3 产品形态

- **入口**：Web 前端（Vue 3）「AI 生产助理」聊天界面，工具调用步骤前端可视化展开、可追溯
- **辅助入口**：生产看板、3D 数字孪生设备监控、告警中心
- **交付**：结构化报告 + 数据表格 + 处置建议，支持多轮追问

### 2.4 Agent 能力清单（对照附录 B）

| 能力 | 实现 |
|---|---|
| 任务理解 | `task_planner.py` 规则意图识别 + 实体抽取（`DEVICE_CODE_RE`） |
| 计划生成 | 意图→工具链映射，执行计划注入 LLM 上下文 |
| 工具调用 | `tools.py` 19 个工具统一执行器（超时/错误规范化/JWT 透传） |
| 知识增强 | `knowledge_base.py` TF-IDF 中文检索（双字词加权+标题重排），6 篇内置手册 |
| 多轮交互 | Redis 会话焦点记忆（30min），"那台设备"指代继承 |
| 上下文管理 | MySQL 对话历史持久化 + 页面上下文注入 |
| 结果交付 | `report_builder.py` 结构化报告（LLM + 规则兜底） |

### 2.5 技术路线

- **架构**：Spring Cloud 2023 六大微服务（网关/认证/工单/工艺/质量/看板）+ .NET 8 设备网关 + Python FastAPI AI 服务
- **设备接入**：MQTT 采集 → Kafka 转发（10000+ 条/秒），InfluxDB 时序存储
- **数字孪生**：Three.js 3D 车间 + 健康评分算法（`_compute_health_score`）
- **模型**：智谱 GLM-4-Flash（Function Calling）、LightGBM/XGBoost（质量/产量预测）
- **Agent 编排**：自研四阶段流水线（非 LangChain，轻量可控），`max_iterations=8` + 100s 超时保护

### 2.6 数据、模型与工具使用方式

| 项 | 说明 |
|---|---|
| 模型来源 | 智谱 AI GLM-4-Flash（商业 API，`ZHIPU_API_KEY`）；LightGBM/XGBoost 自训（开源） |
| 调用方式 | 智谱 SDK `chat.completions.create`，限流 60 次/分 + 结果缓存 1h |
| 数据来源 | 全部为模拟数据：WPF 设备模拟器（5 种场景预设）+ SQL 初始化脚本；无真实企业数据 |
| 知识库 | 6 篇内置设备/质检/工单文档（`knowledge_base.py`）+ `knowledge/` 目录可扩展 |
| 可替代性 | 大模型可替换为开源模型（GLM-4 可换 Qwen 等），Agent 层与模型解耦 |

### 2.7 安全合规边界

- **工业边界**：Agent 只调用只读查询与"创建工单"建议接口，**不直接控制真实设备、不替代现场安全生产决策**，输出明确标注"仅作辅助参考"
- **数据合规**：全模拟数据，本地部署，无个人信息/商业秘密；JWT 鉴权 + RBAC 权限控制
- **风险提示**：工具失败自动兜底、LLM 失败规则兜底、超时保护、不确定结果提示人工确认

### 2.8 后续落地计划

| 阶段 | 计划 |
|---|---|
| 短期（复赛） | 补 Agent 自动化测试、完善工单分派建议（人员技能/备件库存/紧急程度） |
| 中期 | 供应链风险预警（供应商交付周期/物流状态）、生产排产建议（产能/交期） |
| 长期 | 接入真实工业协议（OPC-UA/Modbus）、向量化知识库（ChromaDB）、多模态（现场照片/语音） |
